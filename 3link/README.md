# スリーンク 統合管理ツール

## 概要

株式会社スリーンクの案件管理・依頼者管理・クライアント管理を一元化するツール。
Google Sheets をデータベースとして使い、GAS WebApp からブラウザで操作できる。
案件番号を中心とした縦持ち構造で設計されており、月別横持ち管理の問題を解消する。

## 案件番号フォーマット

```
{依頼者番号}-{顧客番号}-{ジャンル番号}-{日付YYMMDD}-{金額}
例: 1-1-3-260322-16000
    = 依頼者1（まりえ）・顧客1（ゆかぴさん）・ジャンル3（デザイン）・2026/03/22・¥16,000
```

## 案件状態フロー

```
発注中 → 納品待ち → 承認待ち → 請求待ち → 支払待ち → 支払済み
```

- **発注中**: 管理者が案件を登録した直後
- **承認待ち**: 依頼者が成果物を提出した後（自動遷移）
- **請求待ち**: 管理者が承認後（将来実装）
- **支払済み**: 管理者が支払い処理後（将来実装）

## セットアップ手順（初回）

> 通常は不要。スプレッドシートとGASは既に稼働中。

### 1. 認証設定

```bash
# OAuth認証ツールを使用（既存の認証基盤を流用）
# C:\Users\kazuy\.claude\tools\sheets\ の credentials.json・token.json が必要
```

### 2. スプレッドシート作成

```bash
cd C:\Users\kazuy\Projects\3link
python setup_spreadsheet.py
```

→ `config_3link.py` に `SPREADSHEET_ID` が自動書き込まれる

### 3. マスターデータ移行

```bash
python migrate_masters.py
```

→ 依頼者・顧客データを旧会計管理シートから移行

### 4. GASコードのデプロイ

```bash
python deploy_gas.py
```

→ `gas/` フォルダのコードをGASプロジェクトにプッシュ

### 5. WebApp を手動でデプロイ

1. スプレッドシートを開く
2. 「拡張機能」→「Apps Script」
3. 「デプロイ」→「新しいデプロイ」
4. 種類: ウェブアプリ / 実行ユーザー: 自分 / アクセス: 全員
5. デプロイしてURLを取得・記録

## よくある修正パターン

### GASロジックを変更したい

1. `gas/コード.js` を編集
2. `python deploy_gas.py` を実行
3. WebAppを「デプロイを管理」→「新バージョン」で再デプロイ

### WebAppのUIを変更したい

1. `gas/index.html` を編集
2. `python deploy_gas.py` を実行
3. WebAppを再デプロイ

### 新しいシートのヘッダー・バリデーションを変更したい

- `setup_spreadsheet.py` 内の各シート設定を変更
- **注意**: 再実行すると新しいスプレッドシートが別途作成される

### 依頼者・顧客マスターを更新したい

- スプレッドシートの「依頼者マスター」「顧客マスター」シートを直接編集
- WebAppのドロップダウンはGAS起動時に自動読み込み（即時反映）

## 注意事項・依存関係

- **認証**: `C:\Users\kazuy\.claude\tools\sheets\` の OAuth 認証基盤（credentials.json / token.json）が必要
- **Apps Script API**: [https://script.google.com/home/usersettings](https://script.google.com/home/usersettings) で有効化が必要
- **WebAppの通信**: `google.script.run` を使用（`fetch()` はGAS HTML Serviceのsandbox内では使えない）
- **スプレッドシートID**: `config_3link.py` で管理。GASスクリプトID（`GAS_SCRIPT_ID`）も同ファイルに記録
- **WebApp再デプロイ**: GASコードを変更した場合は毎回「新しいデプロイ」が必要（既存デプロイは旧バージョンのまま）
